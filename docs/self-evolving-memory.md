# 自进化经验库（self-evolving memory）

> agent 怎么"越用越少踩坑"：把复发的坑提炼成经验，下次执行前自动召回绕开，再定期体检去重退役。
>
> 这是 v0.5 新增的能力，落在 `lessons.md` + `.claude/scripts/lessons_gc.py` + `closeout` skill 三处。

## 在解决什么

agent 最气人的一点：这轮辛苦踩出的教训，下轮原样再踩一遍。每个会话都是一张白纸。

人类不是这样工作的——你被同一个 bug 咬过两次，第三次就长记性了。这套机制就是给 agent 装上这个"长记性"的闭环，而且**全程可观测、可手改、不黑箱**。

## 闭环四步

```
踩坑 → 提炼(Reflector) → 召回(读回) → 体检(Gate)
  ↑                                        │
  └────────────── 越用越准 ←───────────────┘
```

### 1. 提炼（写入）— 在 closeout 里

收尾时，closeout 有两个时机把经验沉淀进 `lessons.md`：

- **踩坑必提**：你重跑 / 纠正 / 说"不行"时，agent 必问一句"这坑是**结构性的**（换个会话还会踩）还是**一次性的**（网络抽风）？"——只有结构性的才记。
- **收尾轻扫**：每轮收尾自检"有没有值得记的复发经验"，有就提议，没有就明说"本轮无"，不强凑。

写入的经验必须是**条件句**：`当 X → 做 Y`，不是 `永远做 Y`。绝对句会过拟合当时那一个案例，下次场景一变就误导。

### 2. 计数（每条带 meta）

每条经验标题下挂一行机读 meta：

```markdown
## 2026-05-20: 当给 CLI 加"接受用户路径"的功能 → 第一组测试就上奇怪文件名
<!-- meta: id=L004 | scope=cli,用户输入 | applied=2 | helpful=2 | harmful=0 | last=2026-05-20 -->
```

- `scope`：这条适用的场景标签，**召回时按它过滤**。
- `applied / helpful / harmful`：用过几次、帮到/帮倒几次。收尾时按实情 +1。
- `last`：最近应用日期。

### 3. 召回（读回）— 渐进披露

skill 执行**前**，按当前任务的 scope 把相关经验 grep 出来当侧载上下文：

```bash
grep -B1 -A6 "scope=.*用户输入" .claude/memory/lessons.md
```

关键是**按 scope 过滤，不整篇塞**——整篇塞进上下文会让它膨胀、互相干扰，反而退化。命中后 agent 会点一句"历史教训（自动加载）：…"，让你知道哪条经验在起作用。

### 4. 体检（Gate）— lessons_gc.py

经验库只增不减会烂掉：重复条目堆积、新旧经验互相矛盾、过期经验还在误导。`lessons_gc.py` 定期体检：

```bash
python3 .claude/scripts/lessons_gc.py            # dry-run，只报告
python3 .claude/scripts/lessons_gc.py --apply    # 仅归档退役条目
```

- **去重**：scope 重叠 + 标题相似 → 报"疑似重复，建议合并"（**只报告不删**，合并是语义判断，留给你）。
- **矛盾**：同 scope 一正一反措辞 → 报"疑似矛盾，待裁"。
- **退役**：`harmful>helpful` 或长期 `applied=0` → 建议移入 `lessons-archive.md`（`--apply` 才动，只移不删，自动备份可回滚）。

`开工` 时可以顺手跑一次 dry-run，把体检报告随简报给你。

## 设计取舍（踩过的坑，写在这防你也踩）

- **只报告不自动删**：去重和矛盾都是语义判断，机器容易误杀。脚本只提醒，合并裁决永远是人。
- **条件句不写绝对句**：这是整个机制能用的前提。绝对句 = 过拟合。
- **增量不重写**：新增/原地改计数，绝不让 agent 把整个 lessons.md 重写一遍——实践和研究都表明整体重写会让经验库塌缩退化。
- **可靠反馈才记**：有执行结果或你明确反馈才提炼，纯推测不记。记错根因比不记更坏。
- **写入永远要你确认**：agent 只提议，你点头才落盘。沉默 = 不写。

## 这不是什么

- 不是给 agent 加智能——是给它一张能积累、能被你审计的"经验便签"。
- 不是向量数据库——就是带标签的 markdown，你能 `cat` / `grep` / 手改 / `git diff`。
- 不是自动驾驶——每一步写入都等你确认，每一条经验你都能删。

这是骨架，不是教条。scope 标签怎么定、体检多久跑一次、阈值多少，都按你的工作风格调。
