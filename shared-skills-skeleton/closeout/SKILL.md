# Closeout

## 定位

这是任务结束时的统一收尾入口。

它不负责继续扩任务，只负责把这轮做了什么、解决了什么、还能做什么收干净，并在需要时给出记忆更新建议。

## 它在防什么坑

- 事情做完了，但没有留下清楚总结
- 用户不知道现在到底能验证什么
- 当前焦点和待办越来越脏，没人清理
- 没得到确认就擅自写记忆

## 什么时候用

- 任务完成
- 用户说"先这样""停""总结"
- 会话即将结束
- 任务中途叫停

## 不什么时候用

- 任务还在推进中
- 当前只是中间状态，还没到一个自然收口点
- 用户明确要求继续，不需要总结

## 默认工作方式

先收尾，再建议写记忆。

默认顺序是：
1. 先给 6 段总结
2. 如有需要，再给清退建议
3. 最后明确询问是否写记忆

## 6 段输出

```markdown
## 收尾总结

### 我要做的事
[本轮做什么，1-2 句]

### 解决的问题
[解决了什么痛点]

### 目标效果
[用户能看到什么变化]

### 现在用户能做什么
[验证路径]

### 未完成内容
[剩余任务]

### 下一步决策
[等人拍板]
```

## 用户可见检查点

### 检查点 1：必须说清这轮到底做了什么

不能只说"已完成"，要能让用户一眼知道：
- 做了什么
- 解决了什么

### 检查点 2：必须说清现在怎么验证

至少要告诉用户：
- 现在哪个文件、页面或结果可以直接看

### 检查点 3：写记忆前必须确认

无论任务大小，用户没确认前都不写记忆。

## 记忆更新建议

输出后明确询问：
> "建议更新 timeline 和 current-position，确认写入？"

用户明确回复"是/Y/确认"→写入。沉默/忽略/说"否"→不写入。

## 经验提炼（lessons）— 让 agent 越用越少踩坑

收尾时除了流水账，还做一步**批判性提炼**：把本轮真正的复发经验沉淀成 `lessons.md` 一条。这是经验库自进化的来源。两个触发时机：

**时机 A — 踩坑必提（强）**：用户重跑 / 纠正 / 说"不行" / 否掉方向时，必问一句：
> "这次的坑是**结构性的**（换个会话还会再踩），还是**一次性的**（网络抽风、手滑）？"

只有结构性的才提议成 learning。一次性事故不记——记噪音比不记更坏。

**时机 B — 收尾轻扫（弱）**：每次 6 段总结后，自检一句"本轮有没有产生值得记的复发经验？"
- 有 → 提议 1 条（最多 2 条）。
- 无 → 明说"本轮无新经验"。**不强凑**。

提炼出的 learning 必须遵守：

1. **写成条件句，不写绝对句**：`当 X → 做 Y`，不是 `永远做 Y`。绝对句会过拟合这一个案例。
2. **带 meta 行**（给 `.claude/scripts/lessons_gc.py` 体检用，格式见 lessons.md 模板）。
3. **防污染**：根因不确定时，标 `置信度=低` 并写清依据，不把猜测伪装成定论。
4. **仍是草稿**：按确认口径问"确认写入 lessons.md？"，用户点头才写。

## 经验召回（lessons）— 渐进披露

提炼是写入，召回是读回——闭环另一半。skill 执行**前**，按当前任务的 scope 标签从 `lessons.md` grep 出相关条目当侧载上下文：

```bash
grep -B1 -A6 "scope=.*<当前skill或场景>" .claude/memory/lessons.md
```

- **按 scope 过滤，不整篇塞**（防 context 膨胀）。
- 命中后在回复里点一句"历史教训（自动加载）：…"，让用户知道这条经验在起作用。
- 应用了某条 → 收尾时该条 meta 的 `applied +1`；明显帮到 `helpful +1`，帮倒忙 `harmful +1`。
- 这是协议，不强制所有 skill 立刻接；谁需要谁引用。

## 研究模式（可选）

当本轮涉及论文、调研、实验、选题、方法设计、文献分析等研究任务时激活。不替代 6 段收尾，只在其后追加"研究探索记录"。

从对话历史提取事件，每条标 provenance（`user` 用户决策/确认 vs `ai` AI 建议/推断）；不确定来源时写清依据，不把 AI 建议伪装成用户决策。

```yaml
### 研究探索记录
session_date: YYYY-MM-DD
events:
  - type: decision|experiment|dead_end|pivot|claim|heuristic|ai_action
    description: 一句话描述
    provenance: user|ai
```

| type | 提取规则 |
|---|---|
| `decision` | 用户在多个选项中选了哪个，或明确否掉哪个方向 |
| `experiment` | 跑了什么实验/验证，结果如何 |
| `dead_end` | 什么路走不通，为什么放弃 |
| `pivot` | 重大方向变更 + 触发证据 |
| `claim` | 关于方法/数据/结论的关键断言 |
| `heuristic` | 本轮发现的经验法则 |
| `ai_action` | agent 的关键操作（检索/修改/验证/生成） |

## Ideas 回看 + 沟通观察（可选）

- **Ideas 发酵期检查**：若工作区维护了 ideas 池，收尾时回看是否有"发酵够了可以动手"或"放太久该灰化"的想法，提醒用户，不替他决定。
- **沟通切片**：察觉到用户疲惫/烦躁信号（重复纠正、语气变冲、"你有病吧"），收尾时收敛——别硬塞流程，问清真实意图优先于推进任务。这是对话质量的自我观察，不写进记忆。

## 轻量清退

### 定位

- `closeout` 可以对 `current-position` 提出清退建议
- 目标不是删历史，而是让"当前焦点/最近待办/阻塞项"保持新鲜
- **只建议，不自动处理**

### 只处理什么

- `current-position.md` 里的已完成待办
- `current-position.md` 里的已失焦事项
- `current-position.md` 里的长时间阻塞事项

### 明确不处理什么

- 不删除 `timeline.md` 历史记录
- 不删除 `decisions.md` 决策记录
- 不删除 `lessons.md` 复盘记录
- 不做自动归档系统

### 输出方式

如果检测到 `current-position` 有明显过期内容，在 6 段总结后追加：

```markdown
### 清退建议
- 可移除: [已完成事项]
- 可降级: [已失焦但以后可能还会做的事项]
- 可标暂停: [阻塞过久或等待外部输入的事项]
```

### 候选规则

- **可移除：** 本轮已完成，且下轮不再是当前焦点
- **可降级：** 不是当前优先级，但保留为 backlog 更合适
- **可标暂停：** 依赖外部决策/权限/信息，短期内无法推进

### 确认口径

有清退建议时，收尾后的询问改为：
> "建议更新 timeline 和 current-position；另外检测到 3 项可清退/降级，确认一并处理吗？"

用户明确回复"是/Y/确认"→按建议写入 `current-position`

用户回复"只写入，不清退"→只更新正常收尾内容，不处理候选清退项

用户沉默/忽略/说"否"→不写入

### timeline 建议内容

```markdown
## YYYY-MM-DD HH:MM
- **做了什么：** [简述]
- **产出：** [产出物]
- **位置：** [路径]
- **下一步：** [待办]
- **阻塞：** [无 / 原因]
```

### current-position 建议内容（轻量扁平）

```markdown
## 当前焦点
- **正在进行：** [1 句话]
- **优先级：** P0/P1/P2

## 最近待办
1. [事项]
2. [事项]

## 阻塞项
- 无 / [原因]

## 上次更新
YYYY-MM-DD HH:MM
```

### lessons 建议内容

```markdown
## YYYY-MM-DD: 当 X → 做 Y
<!-- meta: id=Lxxx | scope=skill名,场景标签 | applied=0 | helpful=0 | harmful=0 | last=YYYY-MM-DD -->
**场景：** [什么情况下]
**观察：** [发生了什么]
**做法：** [怎么处理的]
**效果：** [结果如何]
**置信度：** 高/中/低
**建议：** [下次怎么做]
```

### decisions 建议内容

```markdown
## YYYY-MM-DD: [标题]
**决策：** [内容]
**背景：** [为什么]
**影响：** [影响什么]
**状态：** 已确认 / 待验证
```

## 不同状态处理

### 正常完成

- 输出 6 段总结
- 如有需要，追加"清退建议"
- 建议更新记忆，等确认

### 用户叫停

- 输出"任务已暂停"
- 列出已完成/未完成
- 建议更新 current-position 为"暂停"
- timeline 建议记录"[暂停] 原计划 X，已完成 Y，剩余 Z"
- 如旧待办已失效，可一并给出清退建议

### 遇到阻塞

- 输出"遇到阻塞"
- 描述问题、已尝试方案
- 建议更新 current-position 阻塞项
- 建议下一步决策
- 对已经不再适合作为当前待办的旧事项，可建议降级或暂停

## 边界与异常处理

收尾本身也会遇到异常。这些情况下 closeout 不硬走流程，明说现状并降级：

| 情况 | 条件 | 怎么处理 | 对用户怎么说 |
|------|------|----------|--------------|
| 上下文不足 | 会话太短/被压缩，看不清这轮做了什么 | 不编 6 段，只写能确认的部分，其余标"未捕获" | "本轮上下文不足，只能确认 X，其余请你补充" |
| 记忆文件缺失 | `.claude/memory/` 或目标文件不存在 | 不创建整套结构，提示先 init-workspace | "未发现记忆文件，需先初始化工作区再写入" |
| 脚本不可用 | `.claude/scripts/` 下脚本不存在或报错 | 跳过该步，不阻断收尾 | "维护脚本不可用，已跳过，收尾照常" |
| 无新内容可记 | 本轮无产出、无经验、无决策 | 不强凑记忆建议 | "本轮无值得落盘的新内容，不建议写记忆" |
| 用户已离开 | 叫停后无回应 | 只输出总结，不写任何记忆 | （静默等待，不写入） |

原则：**收尾失败要可见**——宁可说"这步没做成"，也不假装收干净了。

## 最小验收

这轮至少要做到：

1. 6 段总结完整
2. 用户现在能做什么写清楚
3. 如有必要，给出轻量清退建议
4. 写记忆前明确询问
5. 不借收尾顺手扩新需求
