# Decisions

## 2026-05-15: v0.3 优先做搜索，不做同步

**决策：** notebook-cli v0.3 的核心新功能定为"全文搜索"，跨设备同步推到 v0.4。

**背景：** 之前一直假设同步是用户最痛的点（因为 Obsidian Sync 卖得贵）。但仔细回看自己作为用户的真实使用：90% 的不爽来自"找不到 3 个月前写的某条笔记"，而不是"换了设备打不开"。决定先验证这个假设，做搜索。

**影响：**
- v0.3 周期内不会处理同步相关的任何 PR
- 用户测试访谈的核心问题改成"你最近找不到一条笔记是什么时候"

**状态：** 已确认（2026-05-20 用户访谈印证：5/5 都把搜索排在前两位，2/5 提到同步）

## 2026-05-15: 搜索引擎选 ripgrep 而非自研索引

**决策：** notebook-cli 全文搜索的后端用 ripgrep（通过 subprocess 调用），不自己写倒排索引。

**背景：** 想过用 tantivy（Rust 版 Lucene）做嵌入式索引。但用户笔记规模通常在几千到几万条 markdown 文件，ripgrep 直接扫已经够快（实测 10k 文件 < 50ms）。自己维护索引会带来"索引更新滞后"和"索引损坏修复"两个长期维护负担。

**影响：**
- 部署复杂度低：用户系统装了 ripgrep 就能用
- 不支持模糊搜索 / 语义搜索（v0.5 之后再考虑）
- 文件规模上 10w 后可能需要重新评估

**状态：** 已确认，v0.3 alpha 验证后回顾

## 2026-04-08: 项目代号从 mdnotes 改为 notebook-cli

**决策：** 项目对外名字改为 `notebook-cli`。

**背景：** `mdnotes` 这个名字在 npm 已经被占用，crates.io 也有同名废弃项目，做品牌区分困难。

**影响：** 文档、README、域名（暂不买）、社交媒体名字都要改。

**状态：** 已确认，全部替换完成。
